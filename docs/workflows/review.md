# 工作流：译文审阅与修复

## 目标与权限

用 `source.pdf` 判断当前译文是否达到全文翻译标准。默认 audit/review 只读；
只有用户明确授权 review-and-repair、修复或发布时，才能修改论文资产和
`reading_status`。

- **audit/review**：逐节核对并报告证据，不落盘；严重问题建议
  `translated -> draft`。
- **review-and-repair**：先修复并逐节复核；未完成或未通过时保持 `draft`，
  通过后改为 `translated`。

仓库不保存平行版本账本、内容哈希、审阅身份或永久 waiver。当前 Git commit 是
内容版本，`paper.yaml.reading_status` 是当前发布状态，PR、提交和任务报告保存
审阅过程。

## 审阅范围

默认采用增量审阅：完整处理新论文；重新审阅本次发生实质变化的源文、译文或
资源；处理被新确定性证据点名的论文。论文数量增长、普通依赖升级、工作流文案
变化或新的启发式 warning，不构成全库内容复审授权。全库复审或历史批量修改
必须由用户明确授权。

## 成功标准

- 摘要、正文、结论、附录、图、表、公式、算法、代码和参考文献均已对照原文。
- 首页作者/机构、分类信息、脚注、致谢、收稿记录和其他前后置材料已逐项盘点。
- 漏译、摘要化、数值错误、错位资源、断链和过程残留已修复，否则保持 `draft`。
- 确定性结构、资源和公式错误全部通过；启发式信号已经回到 PDF 人工处置。
- 当前论文的 `make paper-check PAPER_ID=<paper-id>` 通过。

## 独立核对

本项目的“人工核对”指审阅者直接依据 PDF 进行语义和必要的视觉核验，区别于
机械扫描。Codex 流程可由独立审阅代理执行；只有用户或 GitHub 审批规则明确
要求真人批准时，才等待真人。独立审阅者不得是该论文最后一次内容修改者；若
审阅者亲自修复，须由另一审阅者核对最终版本。根代理可安排独立审阅代理完成
单篇审阅，不要求为单篇任务建立批次。

审阅者先从当前 `source.pdf` 读取证据，再判断译文和已有发现；不要以旧报告、
其他代理的结论或发现数量作为正确性依据。可以复用定位和提取工具，不能把
“另一个代理也同意”当作独立证据。标题数量、字符比例、扫描器绿灯和“全篇已看”
的自报都不能代替语义核对。

### 发现、修改与复核

每个拟修改的发现提供：源 PDF 页码和段落/图表位置、可核对的短原句或单元格、
对应译文及差异、建议改法和证据是否有冲突。技术判断与原文引句分开写；未看清
的内容写“待核实”，不写成确定的 `source-native-anomaly`。

修改者（包括根代理）须自己打开当前 PDF 的对应位置，读取上下文后再决定是否
采纳。对否定、公式、数值和标识符，按 translation policy 核对局部字形与提取
文本。若证据支持现有译文，应驳回发现并说明依据；若仍不清楚，保留现文并报告
未解决项，不为满足审阅意见而改写。争议处或已被证据推翻的审阅结论，交由未参与
该修改且未作出该错误判断的审阅者重新核对。

最后一次修改后按下表复核；首次完整审阅不可省略。复用的完整审阅基线、当前
diff、复核范围及结论记在任务报告或 PR 中，不新增永久账本。

| 情况 | 必需的独立复核 |
| --- | --- |
| 新论文的首次完整审阅、没有可信完整审阅基线、源文替换、大范围重译，或已知误读的影响无法界定 | 对当前版本完成 policy 定义的源文清单轮与逐项对照轮 |
| 有可信完整审阅基线，且改动范围明确 | 回源核对所有修改及其关联论证、公式、图表和引用；否定修复要核对完整条件与证明分支，不能只看替换词 |
| 纯格式变化，读者文字、数学、代码、资源与顺序不变 | 核对 diff 和相关渲染，确认内容等价；无需再审未变的全文 |

新论文已有可信完整审阅基线后，其后续修复也按后两行处理。

复核发现同类错误时，扩展到本篇同类位置；不能确定边界时升级全篇审阅，不自动
扩展到其他论文。机械门禁按实际改动运行，状态变更与最终集成门禁仍须完成。
需要平台强制审批身份时使用 GitHub required reviewer，不以自报字段代替。

## 历史高频语义缺陷

最终报告须逐类给出“已核对、无发现”或具体处置：

- **叙述者和责任归属漂移**：系统性把作者自述改成第三人称转述，混淆作者与
  第三方，或改变观察、假设与结论的责任归属。自然省略/共用主语不单独构成缺陷。
- **语气、强度和逻辑关系改变**：否定、`may/can/must`、上下界、近似量、
  因果、必要充分、例外和实验适用条件发生变化。特别检查“相似”是否被加强为
  “相同”，以及条件句是否被增加“只有／才能”。
- **摘要化或补写**：贡献、步骤、实验解释、限制、附录被静默删减，或增加原文
  不存在的总结与结论。
- **技术指代和标识符失真**：变量、算子、类型、代码标识符、集合关系或算法
  顺序被泛化或改写。
- **数字上下文错误**：数值虽对，但单位、指标、分母、基线、数据集、硬件或
  “高/低更好”方向错误；默认配置、调优范围或关闭的功能遗漏也会改变比较边界。
- **图表载荷存在但论断缺失**：缺图注、坐标轴、图例、子图标签、正文引用或
  作者从图表得出的结论。检查正常图片显示时的可见正文；仅在 alt 中存在的
  图注不算完成，已有前置或后置图注则不能重复添加。
- **结构完整但阅读顺序错误**：双栏串栏，脚注归属错误，结论、参考文献或附录
  顺序错位。

经核源确认的原文自身异常单列为 `source-native-anomaly`，说明依据及如何忠实
保留。报告区分“已核对无发现”“发现并处置”“未核对/证据不足”，只声称实际
完成的范围。错误审阅意见要明确撤回，不作为关闭成功的翻译缺陷保留。

## 机械校验边界

硬失败只用于不存在合理例外的确定性错误，例如文件/状态不一致、坏资源路径、
缺失读者载荷、非法 Markdown 结构和公式静态兼容错误。

覆盖率、参考文献编号差、Listing/图片数量差、第一人称计数和 PDF 抽取顺序等
只输出 warning。需要逐篇 waiver 才能工作的规则应降为 warning；确定性规则
若出现误报，应修正规则本身，不能建立 per-paper 例外数据库。

先检查告警所比较的两端是否有效：PDF 双栏是否串行，Listing 是否混入邻栏
正文，图表标题是否关联到相邻的正确载荷。作者机构/地址字段、表头和明确指向
其他论文的作者不是叙述视角漂移。字数比例没有计入保留的英文术语、代码与图像
文字，只能提示核对，不能据此扩写译文或判定全文完整。对仍需人工判断的候选，
在任务报告/PR 记录源文位置和处置结论，不追求 warning 数量归零。

编号说明仅在图片 alt 中、缺少相邻可见图注时，资源检查输出候选 warning。
回源并检查位图与渲染正文后决定修复：图片可能已含图注，或采用其他合法结构。
纯粹将已有图注移到可见正文的修复，核对文字不变、图片顺序与指向不变、没有
重复图注；不要借此重译正文或声称完成全篇语义审阅。

## 提交前流程

1. 未完成修复时将论文保持为 `draft`。
2. 按上述范围完成独立核对并处置所有 warning；修复前执行修改者核源。
3. 将 `reading_status` 改为 `translated`。
4. 运行：

   ```bash
   make paper-check PAPER_ID=<paper-id>
   make catalog
   make check
   make diff-check
   ```

5. 在 PR、提交或任务报告中记录审阅范围、结论和仍存在的证据缺口。

批次中的审阅子代理只执行所分派论文的核对并返回结论；状态更新、目录生成和
仓库级门禁由根代理按 batch workflow 执行，不由各子代理重复运行。

已是 `translated` 的论文若在同一变更中完成修复和复审，最终状态可以仍为
`translated`；CI 会依据源文、译文、资源和相关 `paper.yaml` 的 Git diff
重新运行 scoped gate。若修改未完成或复审失败，必须提交为 `draft`。

## 停止条件

audit/review 在证据报告完成时停止。写模式在译文通过并处于 `translated`，
或发现无法在当前范围可靠修复时停止；后一种情况保持 `draft` 并报告具体缺口。
