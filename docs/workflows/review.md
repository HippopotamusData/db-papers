# 工作流：译文审阅与修复

## 目标与权限

用 `source.pdf` 判断当前译文是否达到全文翻译标准。默认 audit/review 只读；
只有用户明确授权 review-and-repair、修复或发布时，才能修改论文资产和
`reading_status`。

- **audit/review**：按本次范围核对并报告证据，不修改论文；严重问题建议
  `translated -> draft`。
- **review-and-repair**：核源修复后按下述风险划分独立复核；未完成或未通过时保持 `draft`，
  通过后改为 `translated`。

操作权限按 [AGENTS.md](../../AGENTS.md#autonomy)，状态定义与迁移归属按
[metadata workflow](metadata.md#状态与文件)。本流程定义审阅动作和证据交付；
内容判据统一使用 [translation policy](../translation-policy.md)。

## 审阅范围

默认采用增量审阅：完整处理新论文；重新审阅本次发生实质变化的源文、译文或
资源；处理被新确定性证据点名的论文。论文数量增长、普通依赖升级、工作流文案
变化或新的启发式 warning，不构成全库内容复审授权。全库复审或历史批量修改
必须由用户明确授权。

用户要求抽查时，明确所查论文、章节或页码及检查内容。抽查完成只支持该范围的
结论，不等于首次完整审阅，也不能单独作为进入 `translated` 的依据。

用户授权按领域进行质量改进并允许抽样时，先做全范围机械与启发式筛查，再按领域选择风险样本：核心定义和正确性条件、实验配置与限定、公式符号、图注和算法层级、附录/参考文献告警。没有告警的领域也须选样；不只检查告警最多的论文。记录每篇实际检查的位置、确认缺陷、误报、源文自身异常和未检查范围。

发现可界定的共性缺陷后，在用户已授权范围内扩查同类位置；例如列表层级问题同时查有序/无序子项及不同缩进，先排除代码块。可以用 `rg -n '^ {1,3}([-*+] |[0-9]+[.)] )' papers --glob translation.md` 定位候选，再回源和查看渲染；匹配本身不是错误证明，不全库自动替换。缺陷边界无法界定时，按下文风险表扩大核对。

完成选定样本、同类扩查和已确认问题的修后复核后，可关闭本轮抽样任务。报告分别列出全量筛查数、回源样本数和修复数，不将启发式覆盖算作逐句审阅，也不虚构平均质量分数。共性原因改进到现行流程，逐项证据留在任务报告。

用户要求按严重程度抽查时，按对读者判断的影响分级：改变算法行为、正确性条件、
故障保证、方法适用边界或核心实验结论的错误属于重大问题；影响局部且未改变这些
判断的措辞、解释或版式缺陷单独记录。不能因为公式和代码正确就把解释中的条件
倒置降为小问题，也不能只因发现数量多就升级。报告应说明影响、源文证据和实际
检查范围；若用户把修复授权限定为“未发现重大问题时”，须先完成约定抽查并作出
结论，再决定是否进入修复，不边查边改。

## 首次完整审阅与结论范围

首次完整审阅和首次进入 `translated` 必须由独立审阅者完成以下两轮核对：

1. **源文清单轮**：先从 PDF 盘点 policy 要求的全部读者内容，包括首页信息、章节、脚注、图表、公式、算法、代码、结论、致谢、附录、收稿记录和参考文献，再核对译文；不能从译文目录反推完整性。
2. **逐项对照轮**：按 policy 的 [内容与语义](../translation-policy.md#内容与语义)、[结构与读者呈现](../translation-policy.md#结构与读者呈现)、[公式语法](../translation-policy.md#可移植公式语法) 和 [核源方法](../translation-policy.md#核源与呈现核验) 逐项验证。覆盖关键机制、所有显式数字及其单位、指标、基线和实验条件、比较方向、故障边界、否定、限定与结论，不能只抽查代表性数字。代词检索仅辅助定位，不计数或逐词补齐。

确定性缺陷须修复，范围内启发式告警须核源处置，并通过当前论文的单篇门禁。
有可信完整审阅基线的后续修复按下文风险表验证，报告复用的基线和本次范围，
不把未重审部分写成本次全篇核对。只读审阅在证据报告完成时交付，
不执行修复、状态更新或提交门禁。

## 独立核对

本项目的“人工核对”指审阅者直接依据 PDF 进行语义和必要的视觉核验，区别于
机械扫描。Codex 流程可由独立审阅代理执行；只有用户或 GitHub 审批规则明确
要求真人批准时，才等待真人。独立审阅者不得是该论文最后一次内容修改者；若
审阅者亲自修复，须由另一审阅者核对最终版本。根代理可安排独立审阅代理完成
单篇审阅，不要求为单篇任务建立批次。

审阅者先从当前 `source.pdf` 读取证据，再判断译文和已有发现；不要以旧报告、
其他代理的结论或发现数量作为正确性依据。可以复用定位和提取工具，不能把
“另一个代理也同意”当作独立证据。标题数量、字符比例、扫描器绿灯和“全篇已看”
的自报都不能代替语义核对。

### 发现、修改与复核

每个拟修改的发现提供：源 PDF 页码和段落/图表位置、可核对的短原句或单元格、
对应译文及差异、建议改法和证据是否有冲突。技术判断与原文引句分开写；未看清
的内容写“待核实”，不写成确定的 `source-native-anomaly`。

修改者（包括根代理）须自己打开当前 PDF 的对应位置，读取上下文后再决定是否
采纳。对否定、公式、数值和标识符，按 translation policy 核对局部字形与提取
文本。若证据支持现有译文，应驳回发现并说明依据；若仍不清楚，保留现文并报告
未解决项，不为满足审阅意见而改写。争议处或已被证据推翻的审阅结论，交由未参与
该修改且未作出该错误判断的审阅者重新核对。

最后一次修改后按下表复核；首次完整审阅不可省略。复用的完整审阅基线、当前
diff、复核范围及结论记在任务报告或 PR 中，不新增永久账本。

| 情况 | 必需的独立复核 |
| --- | --- |
| 新论文的首次完整审阅、没有可信完整审阅基线、源文替换、大范围重译，或已知误读的影响无法界定 | 对当前版本完成上文的源文清单轮与逐项对照轮 |
| 有可信完整审阅基线，且改动范围明确 | 回源核对所有修改及其关联论证、公式、图表和引用；否定修复要核对完整条件与证明分支，不能只看替换词 |
| 纯格式变化，读者文字、数学、代码、资源与顺序不变 | 核对 diff 和相关渲染，确认内容等价；无需再审未变的全文 |

新论文已有可信完整审阅基线后，其后续修复也按后两行处理。

复核发现同类错误时，扩展到本篇同类位置；不能确定边界时升级全篇审阅，不自动
扩展到其他论文。机械门禁按实际改动运行，状态变更与最终集成门禁仍须完成。
需要平台强制审批身份时使用 GitHub required reviewer，不以自报字段代替。

## 发现记录

按 policy 中的检查对象记录结论：叙述者与责任归属、论断强度与逻辑条件、
遗漏与补写、技术指代与标识符、数字及实验上下文、图表载荷与可见说明、
阅读顺序与结构。质量判据不在报告模板中重新定义。

首次完整审阅逐类说明；局部复核或抽查只展开实际检查的类别，其余可合并标注
范围。使用“已核对无发现”“发现并处置”或“未核对/证据不足”；只读审阅中的
缺陷注明待处理和建议。原文异常按 policy 核实后单列 `source-native-anomaly`；
被证据推翻的审阅意见明确撤回，不作为成功关闭的翻译缺陷计数。

## 告警处置

硬失败与启发式 warning 的划分、校验器整改由 [维护工作流](maintain.md#规则设计)
定义；公式诊断见 [公式维护指南](../portable-math-maintainers.md)。审阅者负责
核实当前范围内的候选，而不是追求 warning 数量归零。

先检查所比较的两端是否有效：PDF 双栏是否串行、Listing 是否混入邻栏正文或
跨页截断、图注是否关联到正确载荷。引用编号差可能来自 OCR、区间或数组；
作者机构/地址、表头或指向第三方的作者不是叙述视角漂移。字数比例未计入保留的
英文、代码和图像文字，不能据此扩写或判定完整性。

候选确认后按实际内容处理；例如 alt 中有图注时，检查图片自身及相邻正文是否
已有可见载荷。仅迁移已有图注的修复按格式变化核对文字、顺序、指向及是否重复，
不借此重译正文或声称全篇审阅。核源位置、误报、未解决候选和处置理由留在
任务报告/PR，不写永久 waiver。范围外告警注明未核对，不据此扩大历史修复。

## 修复交付与门禁

下列步骤适用于已授权的写模式；只读审阅不执行。

1. 修改者核源并修复，按 [格式与公式门禁](translate.md#格式与公式门禁) 验证最后一次修改后的译文。
2. 按风险表完成独立复核，处置本篇和本次修改范围内的告警；记录未检查范围，不将全库 warning 清零作为局部修复的交付条件。
3. 根代理按 [状态与文件](metadata.md#状态与文件) 更新状态：未完成或复审失败保持 `draft`，通过后标为 `translated`。随后必须重新运行 `make paper-check PAPER_ID=<paper-id>`；已有译文在同一变更中完成修复和复审时，最终状态可仍为 `translated`，CI 仍按内容差异复核。
4. 普通整合由根代理运行 `make catalog`，再按 [AGENTS.md 的门禁选择](../../AGENTS.md#commands) 完成仓库级检查；批次遵循 [关闭与集成](batch-translate.md#关闭与集成)，单篇审阅子代理不运行共享生成或仓库级门禁。
5. 报告论文 ID、复用基线、当前修改、实际复核范围、告警处置、门禁及未决证据；审阅过程留在任务报告、PR 或提交中。

## 停止条件

audit/review 在证据报告完成时停止。写模式在译文通过并处于 `translated`，
或发现无法在当前范围可靠修复时停止；后一种情况保持 `draft` 并报告具体缺口。
