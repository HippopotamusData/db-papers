# 工作流：译文审阅与修复

## 目标与权限

用 `source.pdf` 判断当前译文是否达到全文翻译标准。默认 audit/review 只读；
只有用户明确授权 review-and-repair、修复或发布时，才能修改论文资产和
`reading_status`。

- **audit/review**：逐节核对并报告证据，不落盘；严重问题建议
  `translated -> draft`。
- **review-and-repair**：先修复并逐节复核；未完成或未通过时保持 `draft`，
  通过后改为 `translated`。

仓库不保存平行版本账本、内容哈希、审阅身份或永久 waiver。当前 Git commit 是
内容版本，`paper.yaml.reading_status` 是当前发布状态，PR、提交和任务报告保存
审阅过程。

## 审阅范围

默认采用增量审阅：完整处理新论文；重新审阅本次发生实质变化的源文、译文或
资源；处理被新确定性证据点名的论文。论文数量增长、普通依赖升级、工作流文案
变化或新的启发式 warning，不构成全库内容复审授权。全库复审或历史批量修改
必须由用户明确授权。

## 成功标准

- 摘要、正文、结论、附录、图、表、公式、算法、代码和参考文献均已对照原文。
- 首页作者/机构、分类信息、脚注、致谢、收稿记录和其他前后置材料已逐项盘点。
- 漏译、摘要化、数值错误、错位资源、断链和过程残留已修复，否则保持 `draft`。
- 确定性结构、资源和公式错误全部通过；启发式信号已经回到 PDF 人工处置。
- 当前论文的 `make paper-check PAPER_ID=<paper-id>` 通过。

## 独立核对

最终审阅者在最后一次内容修改之后，完整执行 `docs/translation-policy.md`
“审校要求”定义的“源文清单轮 + 逐项对照轮”。该节定义基础清单和方法；本
工作流补充执行时点、报告要求和历史风险类别。标题数量、字符比例、资源数量或
扫描器绿灯不能代替人工核对。审阅者若亲自修改内容，应在修改后重新进行最终
核对；需要强制不同身份时，使用 GitHub required reviewer，而不是仓库内的
自报字段。

## 历史高频语义缺陷

最终报告须逐类给出“已核对、无发现”或具体处置：

- **叙述者和责任归属漂移**：第一人称被改成“本文”“系统”或无主语，或把
  客观陈述擅自改成“我们”。
- **语气、强度和逻辑关系改变**：否定、`may/can/must`、上下界、近似量、
  因果、必要充分、例外和实验适用条件发生变化。
- **摘要化或补写**：贡献、步骤、实验解释、限制、附录被静默删减，或增加原文
  不存在的总结与结论。
- **技术指代和标识符失真**：变量、算子、类型、代码标识符、集合关系或算法
  顺序被泛化或改写。
- **数字上下文错误**：数值虽对，但单位、指标、分母、基线、数据集、硬件或
  “高/低更好”方向错误。
- **图表载荷存在但论断缺失**：缺图注、坐标轴、图例、子图标签、正文引用或
  作者从图表得出的结论。
- **结构完整但阅读顺序错误**：双栏串栏，脚注归属错误，结论、参考文献或附录
  顺序错位。

原文自身异常单列为 `source-native-anomaly`，说明如何忠实保留。逐行定位写进
当前任务报告或 PR，不扩充 `paper.yaml`。

## 机械校验边界

硬失败只用于不存在合理例外的确定性错误，例如文件/状态不一致、坏资源路径、
缺失读者载荷、非法 Markdown 结构和公式静态兼容错误。

覆盖率、参考文献编号差、Listing/图片数量差、第一人称计数和 PDF 抽取顺序等
只输出 warning。需要逐篇 waiver 才能工作的规则应降为 warning；确定性规则
若出现误报，应修正规则本身，不能建立 per-paper 例外数据库。

## 提交前流程

1. 未完成修复时将论文保持为 `draft`。
2. 完成两轮人工核对并处置所有 warning。
3. 将 `reading_status` 改为 `translated`。
4. 运行：

   ```bash
   make paper-check PAPER_ID=<paper-id>
   make catalog
   make check
   make diff-check
   ```

5. 在 PR、提交或任务报告中记录审阅范围、结论和仍存在的证据缺口。

已是 `translated` 的论文若在同一变更中完成修复和复审，最终状态可以仍为
`translated`；CI 会依据源文、译文、资源和相关 `paper.yaml` 的 Git diff
重新运行 scoped gate。若修改未完成或复审失败，必须提交为 `draft`。

## 停止条件

audit/review 在证据报告完成时停止。写模式在译文通过并处于 `translated`，
或发现无法在当前范围可靠修复时停止；后一种情况保持 `draft` 并报告具体缺口。
